# udo-dash Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local, read-only browser dashboard of udo sessions: week, month and day-strip views, To do, side panel, shared highlighting.

**Architecture:** `udo_dash.py` serves `index.html` and four fixed JSON endpoints that each run one read-only `udo` command. `index.html` holds a pure logic script (`<script id="logic">`, testable without a browser) and a UI script.

**Tech Stack:** Python standard library (3.9+), plain JavaScript. Tests: `python3 -m unittest`, and `node --test` (Node's built-in runner, no packages, development only).

**Spec:** `docs/superpowers/specs/2026-11-03-udo-dash-design.md`.

## Global Constraints

- No dependencies, no build step, no network requests from the page.
- Never read `udo.db` or `.udo.toml`. Never run a udo command that can write.
- Server binds to `127.0.0.1`. Session ranges over 100 days are rejected.
- Commits use `git commit -s`.

## Review Focus

- A task or project name starting with `-`: must reach udo as a path, not a flag. Options go first, then `--`, then the path; the path must exist in `udo ls`. Test in Task 1.
- The day clocks change (25 Oct 2026, Vienna): a local day has 25 hours, and sessions still land at their wall-clock position. Test in Task 2.
- A running session across midnight: one piece per day, its end follows now. Test in Task 2.
- A task with no project (root or directly in a workspace): colors, Esc and labels must not crash, and it is highlighted by itself. Test in Task 2.
- A slow response arriving after the user has navigated on must not overwrite the newer view. Sequence token in Task 3, checked in the browser run.

### Task 1: Server

**Files:** Create `udo_dash.py`, `tests/test_server.py`, `README.md`, `.gitignore`

**Interfaces:**
- Produces: `make_server(port: int) -> ThreadingHTTPServer` on `127.0.0.1`; `/`; `GET /api/sessions?from=YYYY-MM-DD&to=YYYY-MM-DD`, `/api/tree`, `/api/node?path=`, `/api/task-sessions?path=`. Success returns udo's JSON unchanged. Errors return `{"error": text}`: 400 for bad input, 403 for a bad `Host`, 502 when udo fails or is missing.

- [ ] Write `tests/test_server.py` using a fake `udo` script placed first on `PATH`, which logs its argv and prints canned JSON. Tests:
  - `test_sessions_runs_exact_args`: argv is `session list / --from "2026-10-26 00:00" --to "2026-11-02 00:00" --json`.
  - `test_tree_args`: `ls / -t --json`.
  - `test_node_args`: `show --json -- <path>` for a path in the tree.
  - `test_task_sessions_args`: `session list --all --json -- <path>`.
  - `test_dash_name_stays_a_path`: path `-x` that exists is passed after `--`.
  - `test_unknown_path_rejected`: 400, and no `show` is run.
  - `test_bad_dates_rejected`: `2026-13-01`, `tomorrow`, missing, and `from >= to` give 400.
  - `test_range_cap`: 100 days is 200; 101 days is 400.
  - `test_bad_host_rejected`: `Host: evil.example` is 403; `localhost:<port>` and `127.0.0.1:<port>` pass.
  - `test_udo_failure_reports_stderr`: exit 1 gives 502 with the stderr text.
  - `test_udo_missing`: empty `PATH` gives 502 with an error.
  - `test_unknown_route_404` and `test_post_rejected`.

### Task 2: Page logic

**Files:** Create `index.html` (logic script only, with an empty shell), `tests/test_logic.mjs`

**Interfaces:**
- Produces a global `L` in `<script id="logic">`, with no DOM access:
  - `dayKey(date)`, `fromKey(key)`, `addDays(date, n)`, `mondayOf(date)`
  - `weekRange(monday)`, `monthRange(firstOfMonth)`, `stripRange(endDay, days)`: each `{from: Date, to: Date}`, `to` exclusive
  - `pieces(rows, range, nowMs)`: `[{id, task, path, day, startMin, endMin, seconds, running, row}]`, one per local day, clipped to the range, rows without a path skipped
  - `fmtSeconds(seconds)`: rounds down to minutes, `7h55`, `4m`
  - `buildTree(lsRows)`: `{rows, byPath, children(path), parent(path), projectOf(path), groupOf(path), containerName(path)}`
  - `colors(tree)`: `{project(groupPath), task(taskPath)}`, each a CSS variable name like `--s1`, `--t3`; `--neutral` for no group
  - `matches(path, hl)`
  - `escStep(state, tree, view)`: mutates `{hl, sel, day, zoom}`
  - `dueState(dueIso, nowMs)`: `{kind: "late"|"soon"|"ok", text}`
  - `todoItems(tree, nowMs)`
  - `tickList(v0, span)`, `zoomAt(zoom, fraction, deltaY)`, `panBy(zoom, minutes)`
  - `weekAxisStart(pieces)`

- [ ] Write `tests/test_logic.mjs` (sets `TZ=Europe/Vienna`, loads the script with `node:vm`). Tests:
  - Ranges: week of 2 Nov 2026 is 2 to 9 Nov; month grid of Oct 2026 is 28 Sep to 2 Nov (5 rows); Feb 2027 is 1 Feb to 1 Mar (4 rows); Aug 2027 is 26 Jul to 6 Sep (6 rows).
  - Cross-midnight: 23:00 to 01:00 in a two-day range gives pieces of 60 minutes each; clipped to the second day alone, one piece of `startMin 0`, `endMin 60`.
  - Running: `end: null` ends at `nowMs`, `running: true`; across midnight gives two pieces.
  - Null path is skipped.
  - DST: on 25 Oct 2026 a session 10:00 to 11:00 has `startMin 600`, `endMin 660`, `seconds 3600`.
  - `fmtSeconds(475.56*60) === "7h55"`, `fmtSeconds(240) === "4m"`, `fmtSeconds(3600) === "1h"`, `fmtSeconds(0) === "0m"`.
  - Tree: `containerName` is the direct parent, null at root; `projectOf` finds the nearest project, null for a task in a workspace or at root; `groupOf` falls back to the workspace, then null.
  - Colors: projects by path through 8 slots; tasks by natural name order (`Exercise 2` before `Exercise 10`), repeat after five; a task with no group gives `--neutral` for its project color.
  - `matches`: a task by itself, a project by prefix, not `Uni/AB` for `Uni/A`.
  - `escStep` ladder per spec: task to project to none to day to zoom; zoom only in `strips`; a task with no project goes straight to none.
  - `dueState`: past gives `late`; 21.5h gives `soon` and `due in 21h`; 40 minutes gives `due in 40m`; 25h gives `ok`.
  - `todoItems`: done excluded, sorted by due, no due date last; left text `1h19 left`, `1m over`, `no estimate`.
  - `zoomAt` keeps the time under the cursor, clamps 60 to 1440; `panBy` clamps at both ends; `tickList(960, 72)` uses 15-minute steps.
  - `weekAxisStart`: 480 by default; a session at 06:20 gives 360.
- [ ] Run `node --test tests/`. Expected: FAIL.
- [ ] Implement the logic script.
- [ ] Run the tests. Expected: PASS.
- [ ] Commit `feat: add page logic for sessions, colors and steps`.

### Task 3: Page UI

**Files:** Modify `index.html`

**Interfaces:** Consumes `L` from Task 2 and the endpoints from Task 1.

Build the UI script from the prototype, applying the spec's "Prototype differences". Requirements not visible in the prototype:

- Every fetch for a view carries a sequence number; a response older than the latest is dropped.
- udo errors show in a banner, and the view stays usable.
- Refetch on navigation and on window focus. Once a minute redraw without a query, unless a zoom or drag happened in the last 2 seconds.
- Sessions are compared by `row.full_id`, so a selection survives a refetch.
- The side panel keeps its scroll position across redraws.
